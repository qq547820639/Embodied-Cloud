# EmbodiedCloud · 具身智能云

**不用买显卡、不用装驱动、不用配环境——打开浏览器，就能开始训练你自己的机器人。**

EmbodiedCloud 是一个"机器人实验云平台"：你选择一个现成的实验模板，平台在云端自动为你准备好 GPU、仿真环境和编码工具，你在浏览器里写代码、跑训练、看仿真结果，几分钟内就能上手，不需要碰任何底层硬件配置。

**适合谁用？**

- **机器人/具身智能的研究者与学生**：想跑 Isaac Lab 强化学习实验，但不想折腾环境安装。
- **高校课程的老师和学生**：用现成模板开实验课，老师管任务、看完成度，学生专注做实验。
- **想验证想法、快速试错的开发者**：先跑通再决定要不要投入自己的 GPU 集群。

---

## 核心功能一览

### 一键创建 GPU 工作区
不再需要"配置 CUDA、装 Isaac Sim、调试驱动"这类费时费力的事。选一个模板、点一下创建，平台自动准备好带 GPU 的工作区，你拿到的是一个**浏览器里的开发环境**（基于开源的 code-server，也就是"浏览器版 VS Code"）。

> **典型场景**：新同学第一天进实验室，5 分钟就能开始跑第一个强化学习实验，而不是花一周装环境。

### 实验模板库
平台预置了一批"开箱即用"的实验模板（模板 = 固定版本的环境 + 固定运行目标 + 验收标准），首批包括：

| 模板 | 一句话说明 |
|---|---|
| Cartpole · RL 入门 | 最经典的强化学习入门实验，用来验证环境是否就绪 |
| Franka Lift Cube · 机械臂抓取 | 训练机械臂把方块抓起来，第一个"正经"应用场景 |
| Franka Pick & Place · 搬运 | 机械臂抓取并搬运物体的进阶任务 |
| Domain Randomization · 域随机化 | 训练"抗干扰"策略，让仿真里学的技能在真实环境更可用 |
| RGB-D Perception · 视觉感知 | 用深度相机数据做物体识别与定位 |

每个模板的版本都是**锁定**的——同一模板任何时候打开，环境都一样，实验结果可复现、可对比。

> **典型场景**：老师布置"跑通 Franka 抓取"作业，学生直接选模板开跑，不用各自写环境配置。

### 浏览器内实时仿真
训练过程中，你能在浏览器里**实时看到仿真画面**（画面通过网页实时传输，技术名称为 WebRTC，简单理解就是"浏览器看直播"）。工作区一旦停止，画面和连接会被妥善清理。

> **典型场景**：跑训练时盯着机械臂的动作，判断策略学得对不对，而不是对着黑乎乎的数字日志猜。

### 数据自动持久化
代码、数据集、训练产出（checkpoint，即训练好的模型权重）都保存在持久化存储中。**即使工作区重建，你的成果也不会丢。**

> **典型场景**：训练中断或工作区需要重启，之前的进度和模型都还在。

### 透明的用量与计费
平台记录每次 GPU 运行的**真实秒数**，账单基于不可变账本生成——账本上的记录只增不改、逐笔可查，你看到的就是实际发生的，同一段运行**绝不会被重复扣费**。当前展示口径为 1 秒 ≈ 1 信用点。

> **典型场景**：跑完一个实验，想知道"这次花了多少"，打开用量页一目了然。

### 安全隔离
每个账号只能访问自己的工作区：别人**看不到、也动不了**你的代码和数据。密码用安全方式加密存储（技术名称 PBKDF2），会话自动管理，不用记一堆乱七八糟的密钥。

### 高校课程支持
老师可以创建课程、把模板挂为实验、邀请学生加入、查看完成情况；学生加入课程后一键启动实验、完成任务。先做教学刚需，不做复杂的管理系统。

> **典型场景**：整班同学同时开课做实验，老师随时看每个人的完成进度。

### 从仿真到真机（Sim2Real）
训练好的模型不是只能停留在仿真里。平台支持把 checkpoint 打包成可部署产物，生成校验码（checksum，用于确认文件没有被篡改），然后推送到真机上的边缘代理，校验通过后即可运行。

> **典型场景**：仿真里训练好的抓取策略，下载到实验室的 Franka 机械臂上真机验证。

## 快速上手

> 要求：一台装有 **Python 3.12 及以上** 的电脑（Windows / macOS / Linux 均可）。全程约 5 分钟。

### 第 1 步：安装

打开终端，进入项目目录后执行：

```bash
make install
```

它会自动创建一个独立的环境（不会影响你电脑上已有的 Python），并装好全部依赖。

### 第 2 步：启动平台

```bash
make dev
```

看到服务启动后，在浏览器打开 **http://127.0.0.1:8000**

### 第 3 步：注册并登录

点击页面上的"注册"，输入邮箱、用户名和密码即可，注册成功即自动登录。注册时也可以填写组织名称，平台会为你创建组织并将你设为拥有者（方便以后和团队成员共享实验）。

### 第 4 步：选择模板，创建工作区

1. 在"模板"列表中选择 **Cartpole · RL 入门训练**
2. 点击"创建工作区"，给它起个名字
3. 工作区会依次经历"已创建 → 排队 → 准备中 → 运行中"几个状态，稍等片刻即变为"运行中"

> 演示模式下这一步是模拟的（不消耗真实 GPU），专门用来让你完整体验产品流程。

### 第 5 步：打开 IDE，跑你的第一个实验

点击"打开 IDE"，在浏览器里进入编码界面，然后运行模板自带的训练命令（Cartpole 是 5 轮迭代的最小训练，很快就能跑完）：

```bash
isaaclab train --rl_library rsl_rl --task Isaac-Cartpole-Direct \
  --num_envs 16 presets=newton_mjwarp --max_iterations 5
```

训练日志和模型文件会保存到工作区的 `outputs/` 与 `checkpoints/` 目录。

### 第 6 步：查看用量与清理

- 在"用量"页查看本次运行的耗时与信用点消耗；
- 训练结束记得**停止工作区**（释放资源、停止计费），不再需要时删除即可。

---

**想更快看效果？** 直接运行一键演示脚本，它会自动启动服务并打开页面：

```bash
./scripts/run_demo.sh
```

## 常见问题（FAQ）与故障排查

**Q1：工作区一直停在"排队 / 准备中"怎么办？**
演示模式下状态会自动推进，稍等几秒即可；若长期卡住，刷新页面。真实 GPU 模式下，这个状态说明 GPU 主机未就绪或正在分配资源，请检查 GPU 主机是否在线。

**Q2：我创建的工作区消耗真实 GPU 吗？**
本地默认是**演示模式（Mock）**，完全模拟、不消耗 GPU。要接入真实 GPU，需要一台装有 NVIDIA 显卡和 Docker 的主机，见 `docs/GPU_HOST.md`。

**Q3：打开页面提示 401 / 未登录，怎么办？**
登录状态过期了。重新登录即可；如果页面一直跳登录，清一下浏览器缓存再试。

**Q4：端口 8000 被占用，启动失败怎么办？**
换一个端口启动即可：

```bash
.venv/bin/python -m uvicorn app.main:app --reload --port 8080
```

然后访问 http://127.0.0.1:8080。

**Q5：我的实验数据会丢吗？**
不会。代码、数据集、checkpoint 都保存在持久化目录中，工作区重建后依然存在。只有你主动"删除工作区"才会清理。

**Q6：为什么账单和我预期的不一样？**
计费基于工作区**实际运行秒数**，停止后才结算。请确认实验期间工作区一直处于"运行中"（停止状态不计费）；如仍有疑问，用量页展示的是不可变账本明细，可逐条核对。

**Q7：怎么重置/清理本地数据？**
```bash
make clean
```
会删除本地数据库、构建产物和演示工作区数据（**请确认没有需要保留的数据**）。

**Q8：想跑真机（Franka 机械臂）验证，现在可以吗？**
模型部署到真机的完整流程（打包 → 校验 → 推送 → 运行）已实现；但**真机验证需要真实机器人硬件**，当前环境无法进行，相关环节如实标记为"待物理验证"，不会谎称成功。参见 `docs/ACCEPTANCE_GATES.md`。

**Q9：忘记密码了？**
当前版本暂无自助找回，请联系管理员重置，或重新注册一个新账号体验。
